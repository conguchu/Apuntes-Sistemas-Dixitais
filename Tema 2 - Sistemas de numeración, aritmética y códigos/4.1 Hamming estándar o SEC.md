***Single Error Correction***: pueden corregir solo un error.

La $d_{min}=3$. 

Pueden **hacerse del tamaño de bits que desee** ($n$) con sus correspondientes bits de paridad ($k$), que se colocan SIEMPRE en las **posiciones** que son **potencia de 2** *(1, 2, 4, 8, 16...)*.

Según el tamaño que tengan:
- **Códigos perfectos**: son **aquellos que cumplen $n = 2^k − 1$** .Para nombrarlos, se usa ($n$, $m$), siendo $n$ los bits totales de la palabra y $m$ los bits disponibles de mensaje. *Como $n = m+k$ (total de bits = bits mensaje + bits paridad), también podemos expresar: $$
k + m = 2^k - 1
$$
- **Códigos acortados**: son **códigos perfectos** a los que **les quitas unos bits de mensaje** porque sobran.   

Sabiendo esto, para saber **cuántos bits de paridad ($k$) necesitamos** para codificar en Hamming SEC un mensaje almacenado que ocupa $m$ bits tenemos que **despejar $k$ en esta fórmula**: $$ k+m<=2^k-1$$

### Codificación de la paridad

En este ejemplo usaremos un **código (7, 4) con paridad par**. Escribimos encima de cada posición su número en binario. Nuestro mensaje en binario puro a codificar es `0100`.

|           | ``001``   | ``010``   | ``011``   | ``100``   | ``101``   | ``110``   | ``111``   |
| --------- | --------- | --------- | --------- | --------- | --------- | --------- | --------- |
|           | **P1**    | **P2**    | **M3**    | **P4**    | **M5**    | **M6**    | **M7**    |
| paso 1    |           |           | ==**0**== |           | ==**1**== | ==**0**== | ==**0**== |
| paso 2    | ==**1**== |           | 0         |           | 1         |           | 0         |
| paso 3    |           | ==**0**== | 0         |           |           | 0         | 0         |
| paso 4    |           |           |           | ==**1**== | 1         | 0         | 0         |
| RESULTADO | **1**     | **0**     | **0**     | **1**     | **1**     | **0**     | **0**     |
1. **Escribimos nuestro mensaje** en los bits de mensaje.
2. **P1** es la paridad de M3, M5 y M7. 
	*Esto porque P1 tiene la posición ``001`` en binario, entonces se calcula su paridad con todas aquellas posiciones donde tengan el último bit activo (`011` = 3, `101` = 5, `111` = 7). Como la paridad es par, buscamos que encendiendo o apagando el bit P1 queden entre esos bits un número par de 1.*
3. **P2** es la paridad de M3, M6 y M7
	*Por el mismo motivo que antes, solo que con el segundo bit porque es la posición `010` = 2*
4. **P4** es la paridad de M5, M6 y M7
	*Por el mismo motivo que antes, solo que con el primer bit porque es la posición `100` = 4*

### Algoritmo de comprobación y corrección de errores

Aprovecharemos la palabra para el mensaje `0100`, que con los bits de paridad ha quedado en `1001100`. Supongamos que hemos recibido el mensaje con un **error en el bit 6**:

|                  | ``001`` | ``010`` | ``011`` | ``100`` | ``101`` | ``110``   | ``111`` |
| ---------------- | ------- | ------- | ------- | ------- | ------- | --------- | ------- |
|                  | **P1**  | **P2**  | **M3**  | **P4**  | **M5**  | **M6**    | **M7**  |
| Mensaje correcto | **1**   | **0**   | **0**   | **1**   | **1**   | **0**     | **0**   |
| Mensaje recibido | **1**   | **0**   | **0**   | **1**   | **1**   | ==**1**== | **0**   |
Para **averiguar si hay error en el mensaje recibido**, hacemos la paridad. A cada bit de paridad que comprobemos le iremos llamando $C_i$. Si la paridad es correcta, escribimos 0 y si no 1.

|             | Paridad de                 | Resultado |
| ----------- | -------------------------- | --------- |
| $$C_1$$     | $$P_1, M_3, M_5, M_7$$     | $$0$$     |
| $$C_2$$<br> | $$P_2, M_3, M_6, M_7$$<br> | $$1$$     |
| $$C_4$$<br> | $$P_4, M_5, M_6, M_7$$<br> | $$1$$     |
Si no hay error, estarán todas las $C = 0$. Si lo hay, la posición del error la indica el número C4 C2 C1, llamádo **síndrome**, que en este caso $= 6$:

| $C_4$ | $C_2$ | $C_1$ |       |
| ----- | ----- | ----- | ----- |
| 1     | 1     | 0     | $= 6$ |
