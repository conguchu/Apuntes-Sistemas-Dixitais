Para representar números con signo en binario tenemos tres diferentes formatos:

- #### Signo-Magnitud (SM)

El **bit a la izquierda** de todo representa el signo del número. **0 es positivo** y **1 es negativo**. El resto de bits representan la magnitud en binario puro del número.

Con $n$ bits podemos representar el intervalo $[-(2^{n-1}-1), (2^{n-1}-1)]$. 
A continuación la tabla de todos los valores representables en SM para $n = 3$ bits.

| Número base 2 (SM) | Equivalente base 10 |
| ------------------ | ------------------- |
| `1 11`             | $-3$                |
| `1 10`             | $-2$                |
| `1 01`             | $-1$                |
| `1 00`             | $-0$                |
| `0 00`             | $+0$                |
| `0 01`             | $+1$                |
| `0 10`             | $+2$                |
| `0 11`             | $+3$                |
*El bit de signo está separado para hacerlo más visual*
Podemos representar con $n$ bits un total de $2^n-1$ números en total (*en este caso p.e. $n = 3$, por ende $2^3-1=7$ números representables*) 

El $-1$ porque el 0 se puede representar en negativo y positivo, siendo equivalentes. 

Quitando el bit de signo, nos quedaría $2^{n-1}$ en vez de $2^n$ para solamente el intervalo negativo o positivo.

- #### Complemento a 1 (C1)

El bit de signo sigue siendo el **situado a la izquierda de todo**. Los valores **0 positivo y 1 negativo** también se mantienen.

Si el número es **positivo** (empieza por $0$) se **representa igual que en** **SM**. Si el número es **negativo** (empieza por 1) se **representa cambiando los 0 por 1 y viceversa**.

*Por ejemplo*, si tenemos el número $5_{10} = 0101_2$ en C1 (que es exactamente igual al SM), para tener el $-5$ haríamos la operación $NOT(0101)$, que queda en $1010_{C1}$

Los bits extra (sobrantes para representar el número) se rellenarían con $1$ igual que se hace con $0$ cuando son positivos: $1111111010_{C1} = 1010_{C1}$ 

Puede representarse el mismo intervalo que cuando es SM, $[-(2^{n-1}-1), (2^{n-1}-1)]$ siendo $n$ el número de bits.

| Número base 2 (C1) | Equivalente base 10 |
| ------------------ | ------------------- |
| `1 00`             | $-3$                |
| `1 01`             | $-2$                |
| `1 10`             | $-1$                |
| `1 11`             | $-0$                |
| `0 00`             | $+0$                |
| `0 01`             | $+1$                |
| `0 10`             | $+2$                |
| `0 11`             | $+3$                |

- #### Complemento a 2 (C2)

El bit de signo sigue siendo el **situado a la izquierda de todo**. Los valores **0 positivo y 1 negativo** también se mantienen.

Si el número es **positivo** (empieza por $0$) se **representa igual que en** **SM**. 

Si el número es **negativo**, se representará como el mimo número en C1 + 1. 

*Por ejemplo*, $25 = 011001_{SM}$, $-25 = 100110_{C1}$, entonces, $-25 = 100111_{C2}$

Esto arregla el problema del $-0$. Esto ya que $000_{SM} = +0$, si invertimos tenemos $111$ y al sumar $1$ nos da de vuelta $000$.

| `0 01`             | `0 01`             | `0 01`             | $+1$                |

| `0 11`             | `0 11`             | `0 11`             | $+3$                |
Al no existir el doble $0$ en C2 queda liberado $100$, que queda para representar $-4$. Esto nos deja con un intervalo representable siendo $n$ el número de bits $[-(2^{n-1}), (2^{n-1}-1)]$

Podemos **pasar de un número C2 a SM** invirtiéndo su parte de magnitud y sumando $1$. 
*p.e.* con el número $-4$ o $100_{C2}$ simplemente haríamos:

$NOT(00) + 1 = 011 + 1 = 100_2 = 4_{10}$, aplicando el 1 en el signo, $-4_{10}$
